Kimi 会员计费的三层结构

先把计费这件事本身说清楚，再看测量结果。

  1. 01

    你付的钱

    ¥199/月，固定。用多用少都是这个价，不超收、不退还。

  2. 02

    你得到的东西

    一根 0~100% 的百分比条。官方只公布档位间的相对倍率和粗略的任务数估算；没有绝对 token 数，没有人民币折算，没有分项费率。

  3. 03

    本报告测出的换算

    全池 = 10,000 credits（1 credit = 0.01%，正好是最小计费刻度）；实测汇率 1 credit ≡ ¥0.10 官方 API 标价 ⇒ 全池 ≈ ¥1,000 标价。下文的「¥」都是这个标价折算，不是你的实付。

  4. 04

    扣费的方式

    每次调用：tokens × 通道费率，折算成 credits 从池中扣除（1 credit = 0.01% 取整，单次最低 1 credit）。Code 与 Work 是两套不同的费率——这就是本报告测出来的东西。

为什么同一件事有两种价格？因为第 04 条的"通道费率"从未公示。同一个 K3 模型、同一池额度， 走 Code 通道便宜，走 Work 通道贵——缓存一项相差 22 倍。下面把两套费率逐一校准。

两个"钱"的口径，别混

标价口径（口径 A）：池子的内部记账单位。说"这次扣费 ¥1.10"，意思是"相当于 ¥1.10 的官方 API 标价"——用来比较通道与任务的相对成本。本页的 ¥ 默认此口径。
实付口径（口径 B）：你真实付出的固定 ¥199/月。走 Code 通道，这 ¥199 约买到 ¥2,540 标价算力；走 Work+iFinD，只买到约 ¥397（见购买力测算）。

解 剖 实 录

41.9 分钟，≈19.5%：一次 Work 任务的完整解剖

2026-09-21 上午，一个"Max effort"深度研究任务：15 个代理、254 条去重模型调用、1,518 万 tokens（93% 为缓存读）。 计费流水逐条合计，这一次任务消耗 20.89%——而当日全天官方计数器仅 25.35%（流水合计 27.96%）， 即这一个任务吃掉了全天消耗的大部分。

官方自己的估算是多少？帮助页写明"一次深度研究 ≈ 5–10% 月度额度"；本次实测同类 Work 任务 ≈19.5%——官方估算上限的近 2 倍。

免 责 与 边 界 声 明

  1. 本页为个人消费计量研究：付费用户测量自己账号的消费记录，属消费者知情权范畴；不构成对任何主体的指控，亦不构成法律意见。
  2. 费率卡为有限信息下的数学反演：全部给出量化区间而非单点断言；凡属解释性内容（如商业逻辑推测）在报告中均已单独标注为推测。
  3. 测量范围为单一账号、单档位、K3 High 模式、2026-09-21 当日；官方可随时调整计费规则，届时本报告相应内容转为历史记录。
  4. 测量误差受 0.01% = 1 credit 计费量化网格限制（单次最小分辨 ≈¥0.10 标价）；我们以区间交集与总量回测双重控制该误差。
  5. 官方对 Allegretto 档位的宣传口径为"Agent 档额度的 4 倍"（档位间相对值）；本报告的「10,000 credits ≈ ¥1,000 标价池 / 5.03×」为实测推算，两者口径不同，均已如实标注。截至测量日，官方未公示任何档位的额度绝对值与池内费率。
  6. 本报告所用接口路径此前已有社区记录，我们的增量是受控实验费率卡与双通道发现；外部价格事实经独立调研核验（核验记录）。
